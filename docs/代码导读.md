## 3. 数据流

```text
rosbag
  │  /hk_camera/image_raw/compressed
  ▼
ft_detector
  │  cv_bridge 解码
  │  BGR → HSV
  │  红/蓝 mask
  │  竖向灯条
  │  左右配对
  │  solvePnP
  ▼
/ft/detection  (ft_msgs/DetectionArray)
  │
  ▼
ft_tracker
  │  Kalman 预测/修正
  │  T 秒提前量
  ▼
/ft/track  (ft_msgs/Track)
  │
  ▼
ft_selector
  ▼
/ft/target  (ft_msgs/TargetSelect)

同时：
ft_detector → /ft/debug/image
ft_tracker  → /ft/debug/marker
ft_detector → TF: camera_optical_frame → armor_<id>
```

## 5. 参数在哪改

### 检测

`src/ft_bringup/config/detector.yaml`

- 话题：`image_topic` / `camera_info_topic`
- 装甲板尺寸：`large_armor_*` / `small_armor_*`
- 配对：`large_gap_ratio` / `max_gap_ratio`
- 反光/距离/重投影：`max_body_v` / `min_distance` / `max_distance` / `max_reproj_error`
- HSV：`red_h_*` / `blue_h_*` / `s_min` / `v_min`
- 动态参数默认值也在这里

### 跟踪

`src/ft_bringup/config/tracker.yaml`

- `T`：提前量
- `gate`：关联门限
- `q_pos` / `q_vel` / `r_meas`：Kalman 噪声
- `max_lost`：丢检删除时间

### 动态调参

```bash
rosrun rqt_reconfigure rqt_reconfigure
```

只暴露了检测的 HSV/面积/配对门限；跟踪参数目前改 YAML 后重新 launch。

## 7. 建议的阅读顺序

1. 先只看 `imageCallback` 的 8 个编号注释（1 组装 header → 8 发布）；
2. 再回头看 `buildMasks` / `detectBars` / `buildPair`；
3. 然后看 `ft_tracker_node.cpp` 的 `callback`；
4. 最后看 launch/YAML，知道参数从哪进来。

每个函数至少能回答：

- 输入是什么？
- 输出是什么？
- 哪个参数会影响它？
- 失败时会发生什么？
